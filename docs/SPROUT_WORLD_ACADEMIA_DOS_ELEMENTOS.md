# Sprout World — Academia dos Elementos

Documento de orientação para continuar mais tarde, com cuidado para não fazer
uma cópia de Roblox/Ninjago. A ideia é criar um **jogo original** inspirado em
aventura, coleção, construção e progresso escolar: primeiro tem de parecer um
jogo divertido; a aprendizagem é a forma de avançar.

---

## Objetivo

Transformar a Sprout numa experiência que a criança queira abrir por vontade
própria:

- explorar um mundo;
- criar e evoluir um herói;
- ganhar pets, fatos, poderes e objetos;
- construir/decorar uma casa/base;
- desbloquear áreas e missões;
- usar a matéria da escola para ganhar energia, moedas, XP e recompensas.

O princípio é:

> O jogo não é um quiz com pontos. O jogo é a motivação; estudar é o motor de
> progressão.

---

## Direção visual

Estilo pretendido:

- aventura 3D/low-poly colorida;
- heróis elementais;
- vilas, templos, cavernas, florestas e montanhas;
- personagens expressivas, mas **originais**;
- pets colecionáveis e evolutivos;
- tom épico, leve e infantil.

Evitar:

- copiar personagens, fatos, nomes, armas ou símbolos de Ninjago;
- chamar ao jogo “tipo Roblox” no produto final;
- usar assets protegidos por copyright;
- transformar isto em escola disfarçada.

Linguagem recomendada:

- **Academia dos Elementos**
- **Guardiões**
- **Cristais de Saber**
- **Energia Elemental**
- **Missões de Conhecimento**
- **Companheiros** ou **Criaturas**

---

## Fantasia principal

Cada criança cria um herói da Academia dos Elementos.

Elementos iniciais:

- Fogo
- Água
- Terra
- Ar
- Luz

Cada elemento pode ter:

- cor principal;
- gesto/poder visual;
- emblema;
- pet inicial;
- árvore de evolução cosmética.

Não há vantagens fortes por elemento no início. A escolha deve ser emocional e
visual, não uma decisão competitiva complicada.

---

## Loop principal

1. A criança entra no mundo.
2. Recebe uma missão curta.
3. A missão pede energia, chave, cristal ou poder.
4. Para ganhar isso, a criança faz uma lição, treino ou teste.
5. A resposta certa dá progresso imediato no jogo.
6. A resposta errada dá explicação e nova tentativa.
7. Ao concluir, ganha recompensa visível: XP, moeda, pet, peça de roupa,
   decoração, carta, poder ou desbloqueio.

Exemplos:

- porta bloqueada numa caverna;
- ponte partida que precisa de energia;
- dragão com escudo que só cai com respostas certas;
- aldeia que melhora quando a turma completa missões;
- pet que evolui depois de testes completos.

## Ligação às matérias

### Matemática

Usar para:

- abrir portas;
- ativar mecanismos;
- calcular distâncias;
- reparar pontes;
- vencer puzzles;
- dar dano a bosses.

Exemplos:

- “Quanto é 45 × 7?”
- “Que dados são necessários para resolver o problema?”
- “Escolhe a estratégia certa antes da conta.”
- “Interpreta o gráfico para encontrar o caminho.”

### Português

Usar para:

- falar com NPCs;
- escolher frases corretas;
- reconstruir mensagens antigas;
- resumir pistas;
- melhorar textos;
- desbloquear pergaminhos.

Exemplos:

- escolher a frase mais clara;
- completar conectores;
- ordenar parágrafos;
- rever uma frase com erro;
- identificar ideia principal de um texto.

### Inglês

Usar para:

- comunicação com criaturas/viajantes;
- listening curto;
- diálogos simulados;
- vocabulário de objetos;
- respostas escritas pequenas.

Exemplos:

- “What is dog?” → “cão”
- escolher a resposta a “How are you?”
- ouvir uma frase e escolher o objeto.

### Ciências / Estudo do Meio

Usar para:

- investigar ambientes;
- curar plantas;
- estudar criaturas;
- resolver experiências;
- restaurar ecossistemas.

Exemplos:

- escolher a conclusão de uma experiência;
- identificar sistema do corpo;
- arrumar etapas do ciclo da água;
- escolher material adequado para uma construção.

### HGP

Usar para:

- desbloquear monumentos;
- reparar linhas do tempo;
- viajar por períodos históricos;
- responder a mapas;
- libertar memória de reis, dinastias e acontecimentos.

Exemplos:

- ligar dinastia a período;
- escolher data correta;
- pôr acontecimentos em ordem;
- identificar monumento e época.

### Cidadania / TIC

Usar para:

- missões de decisão;
- segurança digital;
- responsabilidade;
- assembleia de aldeia;
- dados pessoais;
- pensamento computacional.

Exemplos:

- “Antes de publicar uma foto com colegas, o que fazes?”

Mapa por zonas, alinhado com anos escolares:

- **Floresta Mágica** — 3.º e 4.º ano.
- **Montanhas do Dragão** — 5.º ano.

Cada zona pode ter:

- missões principais;
- missões diárias;
- desafios de matéria;
- NPCs;
- loja;
- área de pets;
- portal para lições;
- boss de fim de zona.

O mundo não precisa de ser 3D na Fase 1. Pode começar como um mapa ilustrado
2D/canvas com zonas clicáveis e evoluir para 3D mais tarde.

### Coleção

- pets;
- cartas;
- emblemas;
- roupas;
- poderes visuais;
- montadas;

Casa/base própria:

- decorar quartos;
- desbloquear móveis;
- mostrar troféus;
- ter pets a passear;

Cada pet tem:

- elemento;
- raridade;
- nível;
- evolução visual;
- habilidade cosmética ou pequena ajuda;
- requisito de evolução ligado a lições/testes.

Evitar pay-to-win. As recompensas devem vir de estudo, consistência e missões.

### Bosses cooperativos

Exemplo:

- **Dragão do Caos**
- vida: 1000;
- cada resposta correta tira dano;
- uma turma/família pode contribuir;
- no fim desbloqueia uma decoração, emblema ou pet.

Para já, isto pode ser assíncrono/local. Multiplayer real fica para mais tarde.

Exemplo:

**Temporada Oceanos**

Missões:

- completar 10 exercícios de Matemática;
- completar 5 de Português;
- completar 3 de Inglês;
- fazer uma lição de Ciências sobre água/oceano.

Recompensas:

- fato oceânico;
- pet aquático;
- decoração de coral;

Criar uma pasta nova:

```txt

```

Possíveis ficheiros:

```txt

apps/web/src/world/Missions.tsx
apps/web/src/world/Pets.tsx
apps/web/src/world/HomeBase.tsx
apps/web/src/world/RewardToast.tsx
```

Estado inicial:

```ts
interface WorldState {
  avatar?: {
    name: string;
    element: "fire" | "water" | "earth" | "air" | "light";
    outfitId: string;
  };
  xp: number;
  coins: number;
  energy: number;
  unlockedZones: string[];
  inventory: Record<string, number>;
  pets: PetState[];
  missions: MissionState[];
  home: HomeState;
}
```

Recompensas derivadas:

- completar lição: +XP, +moedas pequenas;
- completar teste final: +XP grande, +moedas, possível item;
- 3 estrelas: recompensa rara;
- sequência de lições: energia/pet food;
- completar conjunto por disciplina: emblema.

Importante: recompensas devem ser idempotentes. Se a criança repetir o mesmo
teste, não deve farmar moedas infinitas a partir do mesmo evento, exceto se for
uma missão diária/treino desenhada para isso.

## Fases recomendadas

### Fase 1 — Meta-jogo 2D dentro da app

Objetivo: criar o “gancho” sem mundo 3D.

Entregar:

- avatar elemental simples;
- XP escolar;
- moedas;
- energia;
- missões;
- loja/cosméticos básicos;
- recompensas ligadas a testes finais;
- hub visual da Academia.

Usar o que já existe:

- `progress.tsx` para ler lições concluídas;
- `store` para guardar estado do mundo;
- `AchievementsPanel` como inspiração;
- `Diversao` ou novo `World` lazy-loaded.

### Fase 2 — Pets e casa

Entregar:

- pet inicial por elemento;
- inventário de pets;
- evolução de pet com lições/testes;
- casa/base decorável;
- loja de móveis;
- troféus por disciplina.

### Fase 3 — Mapa de aventura

Entregar:

- mapa por zonas;
- missões por ano/disciplina;
- portas/cavernas/templos com desafios;
- bosses locais;
- eventos semanais/temporadas.

Pode continuar 2D/canvas, com animações e som.

### Fase 4 — 3D leve

Entregar:

- uma vila/academia 3D pequena;
- avatar a andar;
- câmera simples;
- portais para lições/missões;
- pets a seguir o jogador.

Tecnologia provável:

- Babylon.js, porque já está no projeto;
- reutilizar padrões de `apps/web/src/diversao/oeste3d/` e
  `apps/web/src/diversao/xadrez3d/`;
- assets próprios/generativos, nunca copiados.

### Especificação completa para o 3D

O 3D deve ser uma evolução da cena 2D, não um recomeço total. Antes de passar a
3D, a Fase 2D deve provar que o loop é divertido. Quando avançar, usar
**Babylon.js**, porque o projeto já tem Babylon em `apps/web/src/diversao/`.

#### Referências internas úteis

Ler antes de implementar:

- `apps/web/src/diversao/oeste3d/Oeste3D.tsx`
- `apps/web/src/diversao/oeste3d/engine.ts`
- `apps/web/src/diversao/xadrez3d/Xadrez3D.tsx`
- `apps/web/src/diversao/xadrez3d/engine.ts`

O padrão recomendado é igual ao dos jogos 3D existentes:

- componente React monta um `<canvas>`;
- uma classe `Engine`/`World3DEngine` possui cena, câmera, luzes e meshes;
- React fica com HUD/overlays;
- Babylon fica com simulação/render;
- limpar tudo no `dispose()`.

#### Estrutura sugerida

```txt
apps/web/src/world3d/
  Academia3D.tsx          # componente React, HUD, overlays, canvas
  engine.ts               # Babylon scene, camera, movement, interactions
  character.ts            # cria hero/pets com primitivas
  map.ts                  # academia/vila, portais, objetos interativos
  controls.ts             # teclado + ponte para joystick touch
  materials.ts            # materiais elementais e tema
  types.ts                # tipos partilhados
```

Não misturar tudo em `Academia.tsx`. Manter a parte 3D isolada reduz conflito e
facilita remover/iterar.

#### Modo de entrada

`#/academia` pode ter dois modos:

- **Modo leve:** cena 2D / dashboard, fallback seguro.
- **Modo mundo:** cena 3D.

Para começar, o botão pode ser:

- “Entrar no mundo”;
- se o dispositivo for fraco ou `prefers-reduced-motion`, manter modo 2D.

Mais tarde, se o 3D estiver sólido, passa a ser a experiência principal.

#### Cena 3D inicial

Criar uma **Academia pequena**, não um mundo enorme:

- praça central circular;
- portal de estudo;
- quadro de missões;
- casa/base bloqueada;
- ninho dos pets;
- mestre/NPC;
- caminho para áreas futuras;
- limites invisíveis para não sair do mapa.

Escala:

- avatar com altura aproximada `1.4` unidades;
- praça com raio `10` a `14`;
- câmera a seguir o avatar a cerca de `8` a `10` unidades;
- evitar mapa gigante na primeira versão.

#### Câmera

Para tablet e crianças, evitar câmera complexa.

Recomendação inicial:

- câmera terceira pessoa, levemente de cima;
- segue o avatar com suavização;
- rotação fixa ou semi-fixa;
- não exigir controlar câmera com dois dedos no início;
- no desktop, rato pode rodar suavemente como extra, mas não é obrigatório.

Parâmetros sugeridos:

```ts
cameraDistance = 8;
cameraHeight = 5;
cameraFollowLerp = 0.12;
cameraLookAt = hero.position + new Vector3(0, 1.1, 0);
```

#### Movimento

Controlo:

- iPad/mobile: joystick inferior esquerdo;
- ações: botões inferiores direitos;
- desktop: WASD/setas + `E`.

Movimento:

- andar em plano X/Z;
- velocidade suave;
- virar o boneco na direção do movimento;
- sem física complexa no início;
- colisões simples com limites e objetos grandes.

Parâmetros sugeridos:

```ts
walkSpeed = 3.2;
turnLerp = 0.18;
interactionRadius = 1.7;
```

#### Interações

O engine deve calcular o objeto mais próximo e expor ao React:

```ts
interface NearbyInteraction {
  id: string;
  label: string;
  action: "talk" | "enter" | "open" | "locked";
}
```

React mostra:

- etiqueta curta acima do objeto;
- texto do botão principal: “Falar”, “Entrar”, “Ver missões”;
- botão de ação no canto inferior direito.

Objetos iniciais:

- `studyPortal`: entrar para estudar;
- `missionBoard`: abrir missões;
- `masterNpc`: diálogo do Mestre;
- `petNest`: ver companheiro;
- `homeGate`: casa bloqueada/requisito.

#### HUD 3D

HUD sempre em React por cima do canvas:

- topo esquerdo: nível + barra de XP;
- topo direito: moedas + energia;
- baixo esquerdo: joystick;
- baixo direito: ações;
- centro/baixo: diálogo curto quando necessário;
- botão pequeno para voltar/sair.

Não meter texto dentro do canvas se React resolver melhor. Texto em canvas/3D
fica pior, menos acessível e mais difícil de traduzir.

#### Performance

Meta:

- correr bem em iPad;
- poucos meshes;
- sombras simples ou sem sombras dinâmicas;
- materiais simples;
- nada de partículas pesadas;
- render loop estável.

Regras:

- usar `engine.setHardwareScalingLevel(...)` como nos jogos existentes;
- limitar `devicePixelRatio`;
- pausar render quando componente desmonta;
- evitar carregar GLBs grandes na primeira versão;
- preferir primitivas Babylon (`MeshBuilder`) e instancing;
- usar texturas só se forem pequenas e realmente necessárias.

### Proporções gerais

Modelo base:

- cabeça grande, cerca de 35% da altura;
- corpo curto, arredondado;
- braços e pernas simples;
- botas grandes para leitura à distância;
- luvas/mãos redondas;
- capa curta ou túnica;
- emblema elemental no peito;
- pet pequeno a flutuar ao lado.

Altura:

```txt
altura total: 1.4 unidades
cabeca: 0.42
tronco: 0.55
pernas/botas: 0.43
```

Silhueta:

- amigável;
- toy-like;
- sem máscara ninja;
- sem armas obrigatórias;
- sem blocos quadrados tipo Roblox;
- sem proporção minifig.

### Construção 3D com primitivas

Usar primitivas para o primeiro modelo:

- cabeça: `MeshBuilder.CreateSphere`, escala levemente achatada;
- corpo/capa: cápsula aproximada com esfera + cilindro/cone arredondado;
- braços: cilindros curtos;
- mãos: esferas;
- pernas: cilindros;
- botas: caixas arredondadas ou cápsulas achatadas;
- emblema: plano pequeno no peito ou mesh simples;
- cabelo/crista: poucas formas triangulares/cones;
- pet: elipsoide + olhos + cauda/asa simples.

Não precisa de rig/esqueleto na primeira versão. Animação pode ser:

- bob vertical ao andar;
- rotação suave do corpo;
- braços balançam com seno;
- pet flutua com seno;
- emblema brilha quando recebe recompensa.

Implementar sem rig:

```ts
root.position.y = baseY + Math.sin(t * 3) * 0.03; // idle
arm.rotation.x = Math.sin(t * 8) * 0.35;          // walk
pet.position.y = baseY + Math.sin(t * 2.2) * 0.12;
```

### Animações boas, não só mínimas

O jogo só vai ganhar vida se os bonecos tiverem animações com personalidade.
Mesmo sem esqueleto/rig complexo, usar animações por partes com `TransformNode`
e seno/interpolação.

Princípios:

- **squash and stretch leve:** cabeça/corpo comprimem 2-4% ao aterrar ou
  celebrar;
- **secondary motion:** capa, cabelo, cachecol, barba e pet atrasam ligeiramente
  em relação ao corpo;
- **anticipation:** antes de usar poder, o boneco inclina e carrega energia por
  0.2s;
- **follow-through:** depois de parar, capa/pet continuam um pouco;
- **idle vivo:** nunca ficar completamente parado;
- **feedback claro:** ação certa deve ter brilho, som curto e movimento.

Estados recomendados:

```ts
type HeroAnim =
  | "idle"
  | "walk"
  | "run"
  | "interact"
  | "cast"
  | "celebrate"
  | "receiveReward"
  | "wrongAnswer"
  | "think";
```

Detalhe por estado:

- `idle`: respiração suave, pet flutua, olhos piscam ocasionalmente.
- `walk`: corpo sobe/desce, braços balançam, pés alternam, capa atrasa.
- `run`: igual ao walk, mas com mais inclinação e passos mais rápidos.
- `interact`: mão levanta, cabeça acena, emblema pulsa.
- `cast`: antecipa para trás, emblema carrega, mão aponta, partícula elemental.
- `celebrate`: salto pequeno, braços sobem, pet gira, brilho no emblema.
- `receiveReward`: moedas/estrelas voam para HUD, personagem faz pose curta.
- `wrongAnswer`: abana a cabeça de forma gentil, sem parecer castigo.
- `think`: mão no queixo/cajado, balão pequeno, olhar para cima.

Tempos sugeridos:

```ts
idleBreathSpeed = 1.8;
walkStepSpeed = 7.0;
runStepSpeed = 10.0;
castChargeMs = 220;
celebrateMs = 900;
rewardMs = 1200;
```

Implementação recomendada:

- função `updateHeroAnimation(hero, animState, dt, t)`;
- cada parte do boneco tem nome estável: `head`, `body`, `leftArm`,
  `rightArm`, `cape`, `pet`, `emblem`;
- não animar com React state frame-a-frame;
- animação vive no engine 3D;
- React só muda o estado: `"walk"`, `"cast"`, `"celebrate"`, etc.

Exemplo:

```ts
function animateIdle(parts: HeroParts, t: number) {
  parts.body.position.y = Math.sin(t * 1.8) * 0.025;
  parts.head.rotation.z = Math.sin(t * 1.2) * 0.025;
  parts.pet.position.y = 1.1 + Math.sin(t * 2.2) * 0.12;
  parts.pet.rotation.y += 0.01;
}

function animateWalk(parts: HeroParts, t: number, speed: number) {
  const step = Math.sin(t * 7 * speed);
  parts.body.position.y = Math.abs(step) * 0.035;
  parts.leftArm.rotation.x = step * 0.35;
  parts.rightArm.rotation.x = -step * 0.35;
  parts.cape.rotation.x = -0.12 + Math.sin(t * 7 * speed - 0.7) * 0.08;
}
```

## Próxima tarefa depois do dashboard

O Claude já criou uma boa **Fase 1 de dashboard** em `#/academia`: criação de
herói, elemento, XP, moedas, energia e missões derivadas do progresso escolar.
O próximo passo é mudar a sensação de “painel” para **mundo jogável**.

Objetivo da próxima iteração:

> Ao abrir `#/academia`, a criança deve sentir que entrou num pequeno mundo,
> não numa página de estatísticas.

### O que falta para parecer mais “mundo aberto”

Adicionar uma cena jogável 2D, ainda simples:

- avatar visível no centro;
- cenário de Academia / vila inicial;
- movimento livre;
- joystick virtual no canto inferior esquerdo;
- botões de ação no canto inferior direito;
- NPCs ou placas com missões;
- portal para “Estudar”;
- portal para “Pets” ou “Casa” mesmo que ainda esteja bloqueado;
- feedback quando a criança se aproxima de um objeto.

Não precisa ser 3D ainda. Um mundo 2D bem animado, com bom toque no iPad, já
vai parecer muito mais jogo do que dashboard.

### Proposta de estrutura

Manter o dashboard atual como “menu do herói” ou “painel da Academia”, mas
adicionar uma cena:

```txt
apps/web/src/world/
  Academia.tsx          # router interno: creator / scene / dashboard
  WorldScene.tsx        # cena jogável 2D
  VirtualControls.tsx   # joystick + botões de ação
  world-map.ts          # objetos, NPCs, portais, colisões simples
  world-state.ts        # estado já existente
  world-data.ts         # economia/missões já existentes
  emblems.tsx           # arte do herói/emblemas já existente
```

`Academia.tsx` pode passar a mostrar:

1. se não há herói: `Creator`;
2. se há herói: `WorldScene`;
3. dentro da cena, botão pequeno para abrir `Dashboard` como overlay.

### Cena jogável 2D

Recomendação técnica:

- começar em React/CSS ou SVG, não canvas obrigatório;
- usar `position: relative` e elementos absolutos num mapa fixo;
- avatar move-se com `transform: translate(...)`;
- câmara simples: mundo maior que o ecrã e viewport centrada no avatar;
- `requestAnimationFrame` para movimento suave;
- respeitar `prefers-reduced-motion`.

Se a cena ficar mais complexa, migrar para canvas depois. Para a primeira versão,
React/SVG é mais fácil de integrar com botões, tooltips, texto e acessibilidade.

### Layout da cena

```txt

│ HUD: nível, XP, moedas, energia          │
│ Missão ativa: Completa 1 teste final     │
```

Objetos iniciais:

### Interações mínimas

Quando o avatar está perto de um objeto:

- aparece etiqueta curta: “Falar”, “Entrar”, “Ver missões”;
- botão direito principal muda para a ação adequada;
- tocar no botão executa a ação;
- no desktop, `E` também pode interagir.

Exemplos:

- perto do Mestre: abre diálogo;

- perto do Quadro: abre overlay de missões;

### Controlos

Criar `VirtualControls.tsx`:

- joystick circular fixo no canto inferior esquerdo;

```ts
interface ControlState {
```

## Regras de design

- A primeira vista deve ser a experiência, não uma página de explicação.
- Usar componentes densos e jogáveis: mapa, avatar, missões, recompensas.
- Nada de UI que pareça formulário escolar.
- Recompensas devem ser visuais e imediatas.
- Botões com ícones; textos curtos.
- Evitar cartas dentro de cartas.
- Testar mobile: isto tem de funcionar bem em tablet.
- Respeitar `prefers-reduced-motion`.
- Não bloquear estudo por “energia” de forma frustrante. Energia deve motivar,
  não castigar.

### Controlos em tablet/mobile

No iPad e em telemóveis, a navegação deve seguir o padrão de jogos tipo mundo
aberto:

- **Canto inferior esquerdo:** joystick virtual para movimento.
- **Canto inferior direito:** botões de ação.
- Tudo deve ficar na zona natural dos polegares, perto da parte de baixo do
  ecrã.
- O centro do ecrã deve ficar livre para ver o avatar, o mapa, NPCs, portas,
  pets e objetos.
- Os botões não devem tapar texto de missão, caixas de diálogo, perguntas ou
  recompensas.

Layout recomendado:

```txt
┌────────────────────────────────────┐
│  HUD: XP / moedas / energia        │
│                                    │
│                                    │
│          mundo / avatar            │
│                                    │
│                                    │
│  ◀ joystick              ação ①    │
│                         ação ② ③   │
└────────────────────────────────────┘
```

Ações iniciais:

- **Interagir** — falar, abrir porta, apanhar item.
- **Poder** — usar poder elemental quando desbloqueado.
- **Saltar / Esquivar** — só se a cena precisar.
- **Mochila / Pet** — pode ficar num botão menor ou menu radial.

Regras práticas:

- joystick com zona grande e tolerante ao toque;
- botões com tamanho mínimo confortável para criança;
- margem inferior suficiente para não bater no gesto/home indicator do iPad;
- esconder ou reduzir controlos quando a criança está numa pergunta/quiz;
- permitir rato/teclado em desktop, mas desenhar primeiro para toque;
- suportar `prefers-reduced-motion`;
- testar em iPad horizontal e vertical, mas priorizar horizontal para o modo
  mundo.

## Regras pedagógicas

- A criança pode errar sem ser punida duramente.
- Erro deve dar explicação e nova tentativa.
- Recompensas maiores devem vir de conclusão e persistência, não só de acertar
  tudo à primeira.
- Não criar mecânicas de vício agressivo: nada de timers manipulativos,
  lootboxes pagas ou pressão social.
- O objetivo é dependência saudável: coleção, criação, orgulho e progresso.
